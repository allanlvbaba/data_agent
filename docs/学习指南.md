## 1. 这个项目能让你学到什么

- **ChatBI / NL2SQL 的工程化落地**:不是调个 API,而是"召回-筛选-生成-校验-修正"的完整工程闭环
- **LangGraph 状态图**:并行节点、条件边回流、流式输出、State/Context 分离
- **混合检索**:向量召回(Qdrant)+ 全文召回(Elasticsearch)+ LLM 精筛的 RAG 组合拳
- **AI 工程安全习惯**:账密环境变量化、.gitignore 纪律、Key 轮换意识

## 3. 环境搭建(Windows,手把手)

1. **装 Docker Desktop** 并配置镜像加速(Settings → Docker Engine 加 `registry-mirrors`,推荐 `https://docker.m.daocloud.io`)——否则拉镜像全靠运气
2. **装 uv**:`pip install uv -i https://pypi.tuna.tsinghua.edu.cn/simple`
3. **拿代码后先配密钥**(两份):
   ```powershell
   cd data-agent
   Copy-Item .env.example .env      # 填 APP_DB_PASSWORD / APP_LLM_API_KEY
   cd docker
   Copy-Item .env.example .env      # 填 MYSQL_ROOT_PASSWORD
   ```
4. **起中间件**:`docker compose up -d`,然后 `docker compose ps` 确认 5 个容器全部 Up
5. **装依赖 + 建知识库**(回到 data-agent 目录):
   ```powershell
   uv sync
   uv run python -m app.scripts.build_meta_knowledge -c ./conf/meta_config.yaml
   ```
6. **起服务**:后端 `uv run fastapi dev` → 前端 `npm install && npm run dev` → 打开 http://localhost:5173 提问

> ⚠️ 全程命令都通过 `uv run` 执行,避免"装在 .venv、跑在全局 Python"的经典错位。

## 5. 节点精读要点(配合断点)

| 节点 | 断点建议位置 | 看什么 | 思考题 |
|------|--------------|--------|--------|
| extract_keywords | 写入 state 前后 | jieba 结果 vs LLM 扩展结果 | 为什么"销售额占比"要拆成多个关键词? |
| column_recall | 检索调用前后 | keywords 如何变成向量、Qdrant 返回几条 | 检索条数(topK)去哪配?多了/少了会怎样? |
| value_recall | ES 命中处 | "Q1"如何命中 `dim_date.quarter.Q1` | 为什么这个用 ES 而不是 Qdrant? |
| merge_retrieved_info | 组装 table_infos 处 | 候选表如何带出各自字段 | 同一字段被两路召回,如何去重? |
| filter_table_info | `chain.ainvoke` 前后 | 进 prompt 的 table_infos 全文 vs LLM 返回的 JSON | 换个问法,LLM 筛选结果会变吗?说明了什么? |
| add_context | date_info 构造处 | 当前日期注入 | 问"上个月销售额"时这个字段如何被用到? |
| generate_sql | prompt 组装完成处 | 完整 prompt 文本 | 哪一段提示词在约束 SQL 方言与只读性? |
| validate_sql / correct_sql | error 写入处 | 触发修正回流的条件 | 如果 LLM 死循环修正,该怎么加熔断? |
| execute_sql | 结果返回处 | 游标结果 → stream_writer | 大结果集(10 万行)会发生什么? |

调试入口:`graph.py` 的 `__main__` 改为 `asyncio.run(main())`,Run/Debug 该文件即可(内置测试 query,不依赖前端)。

## 6. 动手练习(由易到难)

1. **改提示词**:在 `prompts/generate_sql` 中加约束"金额字段保留两位小数",对比效果
2. **加同义词**:给 `dim_product.brand` 加别名"厂商",重建知识库后问"各厂商的销量"
3. **换模型**:把 LLM 从 GLM 换成 DeepSeek(只改 `.env`/yaml,验证 OpenAI 兼容层设计)
4. **加字段**:给 `fact_order` 加 `discount_amount`(折让金额),全链路打通(建列→改 meta_config→重建→问数)
5. **加指标**:新增指标"客单价 = GMV / 订单数",在指标语义层落地
6. **加节点**:在 execute_sql 后加 `format_result` 节点,把结果改写为一句自然语言结论
7. **加熔断**:correct_sql 连续修正 ≥3 次强制失败退出(提示:state 加计数器字段)
8. **前端体验**:结果表格下方加"复制为 CSV"按钮

## 7. 常见坑 FAQ(全部实战踩过)

<details>
<summary><b>展开 13 条(点击)</b></summary>

1. Docker pull 超时 → 配镜像加速;build 阶段 FROM 也要改镜像站前缀(加速器对 build 元数据解析无效)
2. 容器名 mysql 冲突 → 旧容器 `docker rm -f` 或改名
3. 改了 `docker/.env` 里的 root 密码不生效 → MYSQL_ROOT_PASSWORD 只在数据卷首次初始化时生效
4. initdb SQL 不执行 → 数据卷非空;手动导入或删卷重建(见开发文档 §10)
5. MySQL 1044/1045/1146 → 分别是"无权限/密码错或端口被抢/表不存在",先分清再动手
6. 本机装过 MySQL 抢了 3306 → docker ps 显示映射不代表绑定成功,用 netstat 查端口归属
7. YAML 报 `expected '<document start>'` → 顶层键前混进了空格
8. `'uv' 不是内部或外部命令` → uv 没装或没重开终端
9. 装了依赖还是 ModuleNotFoundError → 跑错解释器,一律 `uv run`
10. glm 模型报 `Unable to infer model provider` → 显式 `model_provider="openai"` + `base_url`
11. PyCharm 调试器 UnicodeDecodeError → pydevd 中文截断缺陷,升级 IDE 或打增量解码补丁
12. Debug main.py 秒退 → main.py 只定义 app 不起服务,用 Module uvicorn 方式
13. embedding 报 Connection was reset → 8081 被占或代理劫持,`NO_PROXY=localhost,127.0.0.1`

## 8. 术语表

| 术语 | 含义 |
|------|------|
| ChatBI / NL2SQL | 用自然语言查询数据库的技术统称 |
| 语义层 / 指标 | 把"GMV=订单金额总和"这类业务口径结构化管理,别名用于命中口语表达 |
| 向量召回 | 文本→向量→相似度检索,适合语义模糊匹配 |
| 全文召回 | 关键词倒排检索(ES+IK),适合短枚举值精确命中 |
| 召回-筛选两段式 | 先宽召回保召回率,再由 LLM 精筛保准确率 |
| SSE(Server-Sent Events) | HTTP 单向流式推送,本项目过程与结果都走它 |
| State / Context | LangGraph 中"业务数据载体"与"依赖注入容器"的分离 |
