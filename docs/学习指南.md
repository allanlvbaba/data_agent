## 4. 代码导读法:三遍读完(总代码量 < 1500 行,核心 < 800 行)

### 第一遍:顺着数据流读(理解"一条查询怎么变成结果")

按数据在 State 中被填充的顺序读:

```
1. app/agent/state.py          ← 先背下 State 字段表(开发文档 §7.1),这是全书目录
2. app/agent/nodes/extract_keywords.py   ← State["keywords"] 怎么来
3. app/agent/nodes/column_recall.py      ← State["retrieved_columns"] 怎么来
4. app/agent/nodes/value_recall.py       ← ES 路:与 column_recall 逐行对比异同
5. app/agent/nodes/merge_retrieved_info.py ← 最复杂的一个:值回填/指标拉列/主外键补齐
6. app/agent/nodes/filter_table_info.py  ← LLM 怎么裁剪
7. app/agent/nodes/generate_sql.py       ← 上下文怎么注入 prompt
8. app/agent/nodes/validate_sql.py → correct_sql.py → execute_sql.py
```

### 第二遍:顺着调用链读(理解"请求怎么进、流怎么出")

```
main.py → app/api/routers/chat_router.py(SSE 组装)
        → app/api/deps.py(依赖注入树:逐个数 Depends)
        → app/service/chat_service.py(astream 的入参:State 与 Context 分别是什么)
        → app/core/lifespan.py → app/clients/*(五个管理器)
        → date-agent-frontend/src/App.vue(对端怎么解析 SSE)
```

### 第三遍:顺着"知识"读(理解"数据从哪来")

```
conf/meta_config.yaml → app/config/meta_config.py(schema 定义)
  → app/service/meta_knowledge_service.py(五步构建流水线,开发文档 §6)
  → app/repositories/qdrant/base_repository_qdrant.py(ensure/upsert/search)
  → app/repositories/es/value_es_repository.py(mapping/bulk/query)
  → prompts/*.prompt(8 个文件,对照 §7.5 的解析表)
```

## 6. 提示词工程实战小课(以 filter_table_info.prompt 为例)

打开 `prompts/filter_table_info.prompt`,逐段拆:

| 片段 | 设计意图 |
|------|----------|
| "你是一名查询规划专家…裁剪出必需的表和字段" | **窄角色**:只裁剪,不生成——角色越窄,输出越稳 |
| "仅保留必需…缺少任一关键表都无法准确回答" | 定义入选标准为"必要性",而非"相关性"——防止 LLM 滥竽充数 |
| 规则 1"禁止新增表/字段/改名" | 防幻觉:输出空间被锁死在候选集内 |
| 规则 2"入选表至少一个入选字段" | 保证输出 JSON 的结构自洽(空表无意义) |
| 规则 4 四类语义映射(时间/人群状态/行为/指标) | 把"哪些字段必须留"的判断**显式规则化**,不依赖模型自觉 |
| 规则 5 歧义消歧字段必须保留 | 提示词里最容易被忽略的一条:查询规划要为下游"兜住歧义" |
| 输出格式 `{"表名1":["字段1",...]}` + "仅输出 JSON" | 与代码 `JsonOutputParser()` 严格对应;坏一个引号整个节点进 except |

**对比记忆**:`generate_sql.prompt` 用 `StrOutputParser`,所以它的提示词花了整整一条规则"严禁```sql 等 Markdown 代码块"——**输出解析器决定提示词的最后一条纪律**,这是 LCEL 工程的核心心法。

## 7. LangGraph 概念对照表(本项目用到的每一个 API)

| API | 出现位置 | 在本项目中的作用 |
|-----|----------|------------------|
| `StateGraph(state_schema=..., context_schema=...)` | graph.py:31 | DataAgentState 管业务数据;DataAgentContext 管依赖注入 |
| `add_node(name, fn)` | graph.py:33-44 | fn 签名 `async def node(state, runtime)`;返回 dict 即状态增量 |
| `add_edge` | graph.py:46-62 | 固定拓扑;**注意 correct_sql 缺出边的教训**(§12-K1) |
| `add_conditional_edges` | graph.py:60 | `lambda state: "execute_sql" if state["error"] is None else "correct_sql"` |
| `compile()` | graph.py:63 | 得到 CompiledStateGraph |
| `astream(input, context, stream_mode="custom")` | chat_service.py:40 | custom 模式 = 只透传 `stream_writer` 写的内容(stage/result) |
| `runtime.stream_writer` | 每个节点第一行 | 向前端 SSE 实时推事件——过程可见性的全部实现只有一行代码 |
| `Runtime[Context]` / `runtime.context` | 各节点签名 | 类型化取依赖,替代把 repo 塞进 state(经典反模式) |

## 9. FAQ(14 条,全部实战踩过)

1. Docker pull 超时 → 加速器;**build 阶段加速器无效**,改 FROM 前缀
2. 容器名 mysql 冲突 → 删/改名旧容器
3. 改 root 密码不生效 → MYSQL_ROOT_PASSWORD 只在数据卷首次初始化生效
4. initdb SQL 不执行 → 数据卷非空;手动 `docker cp`+`exec` 导入
5. MySQL 1044/1045/1146 → 无权限/密码错或端口被抢/表不存在,先分清
6. 本机 MySQL 抢 3306 → `netstat -ano`+`tasklist` 查端口归属,docker ps 不代表绑定成功
7. YAML `expected '<document start>'` → 顶层键混入空格
8. `'uv' 不是命令` → 装 uv;装了依赖还报错 → 检查是否跑在全局 Python,一律 `uv run`
9. glm 报 `Unable to infer model provider` → 显式 provider+base_url
10. PyCharm 调试器 UnicodeDecodeError → pydevd 中文截断缺陷(2024.3),升级/补丁/改 pdb
11. Debug main.py 秒退 → 它只定义 app;用 Module uvicorn 跑
12. embedding Connection was reset → 8081 被占或代理劫持,配 `NO_PROXY`
13. `model must be a repo ID, not a URL` → 锁 langchain-huggingface 旧版或改 OpenAIEmbeddings 接 TEI
14. 步骤条停在"校正SQL"没结果 → §12-K1(correct_sql 无出边),练习 7 顺路修掉
